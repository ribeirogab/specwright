# Run Skill Contract — Learnings

- The three shipped sw-run copies are byte-identical from line 3; the only allowed divergence is the frontmatter `name:` line (`run` vs `sw-run`). The safe edit pattern is: edit `.agents/skills/sw-run/SKILL.md` as canonical, then rebuild each sibling as `head -2 <sibling>` + `tail -n +3 <canonical>` — this propagates `description:` changes too, so a description edit needs no per-copy handling.
- `skills/sw/scripts/quick_validate.py` and `package_skill.py` need `pyyaml`, which the system python lacks; `uv run --with pyyaml python skills/sw/scripts/quick_validate.py <skill>` works without touching the environment.
- The board template (`skills/sw/scaffold/templates/board.md`) restates the run skill's ready rule at line 11 — any change to the readiness contract must be mirrored there or the two drift (this issue mirrored the own-branch reading).
- Gap for `issue-pipeline-contract`: the plan skill's circuit-breaker (`.agents/skills/sw-plan/SKILL.md` "Circuit breaker" paragraph, and its two sibling copies) still says only "write that report ... return it to the orchestrator" — it never states the owner must deliver the paste-ready Blockers block (Why / Tried / Needs) that the run skill now requires the conductor to paste unmodified. Flagged by review lane C on PR #49; out of this issue's scope.
- The repo PR template's checklist item "No edits under `.specwright/`, `.agents/`, or `.claude/`" cannot be honestly ticked by a dogfood issue PR — annotate it as intentionally unticked instead of silently ticking (accepted on PR #49).
