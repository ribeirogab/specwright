# Rewrite /sw as /sw:init — Learnings

- **Final `/sw:init` layout**: the skill body lives at `plugins/sw/skills/init/SKILL.md` (frontmatter `name: init`). It performs exactly three additive, idempotent filesystem operations against the repo it's run in: scaffold `.specwright/{conventions,issues,milestones}/` (seeding `conventions/README.md` only when that directory is empty), write or top-up a root `CLAUDE.md` from `plugins/sw/references/claude-md-template.md`, and append `.specwright/worktrees/` to `.gitignore` when absent. It writes zero machine configuration — no `.claude/settings.json`, no skill self-copy, no per-agent symlinks — because the plugin already serves every `/sw:*` command globally.
- **`claude-md-template.md` is the new entry-point template location** (renamed from `agents-md-template.md`) — `plugins/sw/references/claude-md-template.md`. It generates `CLAUDE.md` directly (no `AGENTS.md`, no symlink); its `## Skills and slash commands` section states the `sw` plugin requirement and both install commands (`claude plugin marketplace add ribeirogab/specwright`, `claude plugin install sw@specwright`) as fixed text, not project-specific substitution. Exactly two double-brace placeholders survive in the template body: the project-name token and the project-slug token.
- **`plugins/sw/references/audit-checklist.md` and `validation.md` were trimmed to 3 files/6 numbered checks respectively** — every section about `.claude/settings.json`, `.agents/skills` self-copy inventory, per-agent symlinks, and legacy pre-plugin migrations was deleted outright (that repo state cannot exist under the plugin-only model). What remains: the three vault directories, `CLAUDE.md`'s required headers/size-cap/plugin-requirement line, and the `.gitignore` line.
- **`plugins/sw/references/claude-plugin-settings.md` was deleted outright** (not rewritten) — nothing in the content-only model reads or writes `.claude/settings.json`, so the file had no remaining audience. `plugins/sw/references/vault-files.md` needed no change at all — it already described only the three vault directories with no settings/self-copy content.
- **`validate-spec.sh`'s placeholder check (check 3) greps for the literal double-brace opening marker and has no way to distinguish "prose describing a placeholder" from an actual unfilled template placeholder.** Any spec/tasks/issue prose that needs to *talk about* double-brace tokens (e.g. explaining a template's fill rules) must describe them without ever typing the literal marker — say "double-brace placeholder token" or name the token in words, never reproduce the actual bracket characters. Hit this four times while writing `spec.md`/`tasks.md`/`issue.md`/this file before the pattern was clear.
- **AC-5's banned-string list must be avoided even in negated/explanatory prose, not just as "real" mentions.** A sentence like "no `.claude/settings.json` is written" still contains the literal banned string and fails a literal grep-based AC. The skill's "Does not do" section and the rewritten reference docs had to be worded around this (e.g. "no plugin-trust or plugin-enablement configuration" instead of naming the file), which is stylistically awkward but was the only way to satisfy the AC's literal wording while still being clear to a human reader.
- **A `.gitignore` append via plain `echo ... >>` is unsafe when the file has no trailing newline** — it concatenates onto the file's last existing line instead of starting a new one, which a bare `grep -cxF` count-of-1 assertion does not catch (the new content is still there, just glued onto the previous line, corrupting that line). Any skill appending a single line to a user-owned file should guard with a trailing-newline check first (`[ -s file ] && [ -z "$(tail -c1 file)" ] || printf '\n' >> file`) before the append. Caught by the Opus review's issue-conformance lane, not by mechanical testing — worth remembering as a class of bug validate-spec.sh-style mechanical checks can't catch.

(2) `plugins/sw/references/vault-files.md` still says templates/validator ship at `scaffold/templates/`/`scripts/` (stale — real paths are `plugins/sw/templates/`/`plugins/sw/scripts/`), but that file was explicitly declared unchanged by this issue's spec; whichever issue next touches `vault-files.md` should fix those two paths.
