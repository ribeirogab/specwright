# Plugin-only Restructure — Learnings

- **Final locations**: artifact templates at `plugins/sw/templates/{issue,spec,tasks,goal,board}.md`; the mechanical validator at `plugins/sw/scripts/validate-spec.sh` with its fixtures at `plugins/sw/scripts/fixtures/`; the vendored scaffolder scripts (`quick_validate.py`, `package_skill.py`, `__init__.py`) at `plugins/sw/scripts/`; the reference docs at `plugins/sw/references/{agents-md-template,audit-checklist,claude-plugin-settings,validation,vault-files}.md`; the reconciliation engine at `plugins/sw/scripts/sw-update.sh`. Reference-path convention going forward: any skill/command needing one of these no longer needs the old "installed plugin vs. specwright dev repo" dual-phrasing — there is exactly one location in both cases now.
- **`plugins/sw/scripts/sw-update.sh` was moved verbatim, not redesigned** — its `managed_pairs()` function and self-test fixtures still hard-code the retired three-copy companion-skill-sync model (`.agents/skills/sw-<name>/SKILL.md` ↔ `<clone>/skills/sw/scaffold/skills/sw-<name>/SKILL.md`), because those paths describe an **installed target repo's own tree** and the **upstream release clone**, not this repo's own trees — redesigning the engine for the single-copy plugin model is `remove-sw-update`'s entire purpose. `remove-sw-update` should expect to either delete this file outright or substantially rewrite `managed_pairs()`/`_selftest_apply()`; do not assume it is already plugin-model-aware.
- **`plugins/sw/references/{agents-md-template,audit-checklist,validation}.md` were relocated verbatim and still describe the retired `/sw` scaffolder's own audit/self-copy/per-agent-symlink mechanics** — they were the reference docs of the `skills/sw/` scaffolder skill (now deleted), not of any of the 5 companion skills. `rewrite-sw-init` should expect to substantially rewrite or delete these three files' content once `/sw:init` exists; they were not touched here beyond the move.
- **AC-3-style "grep the whole repo for a literal string" acceptance criteria need an explicit historical-record carve-out stated up front**, or the owner ends up litigating it mid-implementation. This repo's `/sw:review` documentation-consistency lane already exempts shipped issues/milestones from doc-staleness findings (`plugins/sw/skills/review/SKILL.md`); the same principle was applied here for AC-3, but it required a genuine judgment call under time pressure — future tickets with a repo-wide grep-based AC should either state the shipped-issue exemption in the AC's own wording, or explicitly say it applies with no exceptions (forcing ~60 historical-file edits) — leaving it implicit invites exactly the back-and-forth this issue had.
- **A repo-wide string grep AC will also catch genuinely irreducible hits that are not dangling references at all** — a path pointing at the end user's own machine (`install.sh`'s `CANONICAL`/`ln -s`), or at another repo's tree entirely (an installed target repo, an upstream release clone). These are not defects; rewording them to dodge the grep would misdescribe real behavior. Distinguish "matches the string" from "is a stale reference to something this repo just moved/deleted" — they are not the same test.
- **`quick_validate.py`/`package_skill.py` need a Python with `pyyaml`; the default `python3` on this machine doesn't have it and is externally-managed (PEP 668, blocks a bare `pip install`).** A throwaway `python3 -m venv` + `pip install pyyaml` inside it works cleanly without touching system Python — faster than hunting for an alternate interpreter.
- **`git mv` preserves the executable bit** — confirmed across all three moved shell scripts (`validate-spec.sh`, `sw-update.sh`, `install.sh` untouched) and the brainstorm skill's `start-server.sh`/`stop-server.sh`; no `chmod +x` needed after any move in this issue.
- **`skills/sw/`'s parent `skills/` directory becomes a genuinely empty, untracked-by-git directory once its only child is emptied by `git mv`** — git doesn't track empty dirs, so after moving every file out, `skills/sw/{references,scaffold,scripts}` and then `skills/` itself are stray filesystem-only empty directories that `git rm -r` won't remove (nothing tracked inside them). Needed a manual `rm -rf`/`rmdir` sweep after the `git mv`s to get AC-2's "does not exist" bar to hold literally.
