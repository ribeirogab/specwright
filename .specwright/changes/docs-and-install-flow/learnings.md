# Docs and Install Flow — Learnings

- **Entry-point document convergence (`AGENTS.md` → real `CLAUDE.md`)**: the dogfood repo carried `AGENTS.md` as the real file plus a `CLAUDE.md` symlink pointing at it — a pre-plugin leftover. Converging is `git rm CLAUDE.md` (drop the symlink) then `git mv AGENTS.md CLAUDE.md`, which git records as a rename (history preserved). This matches what `/sw:init` already generates for adopters (`plugins/sw/references/claude-md-template.md` produces a real `CLAUDE.md`, never `AGENTS.md`, no symlink). After the rename the file needs an internal self-reference swept (its own milestone step-3 prose said "promotes learnings to `AGENTS.md`").

- **`AGENTS.md` was still named in three *live* plugin-behavior files, not just docs**: `plugins/sw/commands/spec.md`, `plugins/sw/skills/run/SKILL.md`, and (five times) `plugins/sw/skills/review/SKILL.md` generically referenced `AGENTS.md` as the entry-point document any adopting repo has. These are live behavior — `/sw:review`'s own documentation-consistency subagent (C) would flag an `AGENTS.md`→`CLAUDE.md` rename as doc-staleness while its own instructions still said to audit "the `AGENTS.md` homes". The review skill also still described auditing "the three kept-in-sync copies of any touched companion skill" — a model `plugin-only-restructure` eliminated earlier in this milestone. Any Claude-only-plugin doc pass must sweep `plugins/sw/**` for these, not just the top-level `README`/entry-point files. The spec-document-reviewer subagent catches this class if pointed at the actual current file contents.

- **AC-5-style "grep the whole repo for X returns nothing" criteria are unsatisfiable literally** once `.specwright/` holds shipped issue records: prior issues' `issue.md`/`spec.md`/`tasks.md`/`learnings.md` legitimately mention the retired artifact (they document its removal or predate it), and the vault convention forbids retroactively editing shipped issues. The workable reading is "no *live* documentation pointer remains": verify with two greps — a raw `grep -rln X .` (to show the historical noise is understood) and a scoped `grep -rln X . --exclude-dir=.specwright --exclude-dir=.git` (the actual pass/fail signal) — and record both in the PR body. This matches the precedent set by `rewrite-sw-init`'s AC-5, which scoped its grep to specific live directories rather than the whole tree.

- **The merged plugin/marketplace manifests are the canonical companion roster** after this milestone: `plugins/sw/.claude-plugin/plugin.json` and `.claude-plugin/marketplace.json` both list `init, brainstorm, plan, run, review, pr` (companion skills) plus the `spec`/`review-spec` commands — no `update`. The `plugin.json` `description` conflict between `feat/rewrite-sw-init` (`init` in) and `chore/remove-sw-update` (`update` out) resolves to the union: both `init` in and `update` out. Any future doc listing the companion set should match these two manifests.

- **A shell test whose subject file is being deleted must be rewritten, not deleted**, to keep coverage meaningful without a silent count drop. `tests/install/run.sh` unit-tested `install.sh`'s internal functions (merge engines, `configure_plugin`, `remove_legacy_commands`, …); with `install.sh` gone those have no subject. The rewrite asserts the plugin-only reality instead (manifest validity + companion set, init skill present, update skill/script absent, no live doc references the deleted installer). Assertion count dropped 20 → 17 — an intentional, in-PR-documented reduction, not a silent regression. The new test itself names `install.sh` to check its absence, so its own AC-5-style "no live doc references install.sh" self-check must exclude `tests/install/run.sh` from the grep.
